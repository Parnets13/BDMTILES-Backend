# FIFO-aware quotation stock readiness and atomic conversion

The change moves quotation availability to a server-owned, live exact-bucket allocator, exposes that readiness on quotation reads, and uses the same allocation immediately before transactional Sales Order conversion. Approved and accepted quotations compete through a persisted FIFO timestamp, while converted draft orders reserve stock during credit approval and release it when approval is rejected. The rejected out-of-stock Sales Order/GRN-promotion workflow has been removed; GRNs become visible through ordinary Stock reads instead. **Watch for:** **confirmed** duplicate quotation lines can be reported short despite a feasible exact-bucket assignment; **likely** overlapping automatic list refreshes can overwrite newer filters/readiness; **likely** each poll performs an unbounded branch-wide FIFO recomputation; **confirmed** Sales Executive ownership remains absent from Sales Order stats and mutations.

**Verdict**: NEEDS_CHANGES

## High-level view

Quotation creation and edits now snapshot availability on the server, while list, detail, manual stock checks, and conversion calculate current readiness from live Stock rows. The allocator returns the required partial/all/mixed/zero behavior and respects warehouse, shade, and batch constraints, but its largest-bucket-first choice makes readiness depend on duplicate-line order and can block a conversion that reservation could satisfy.

Conversion remains one transaction across the quotation state change, Sales Order creation, exact Stock decrement/reservation, approval request, and confirmed-order ledger posting. Credit-approval drafts reserve immediately, approval rejection releases inside the approval transaction, and approval later calls reservation idempotently rather than decrementing twice.

FIFO virtually consumes live stock for every non-expired approved or accepted quotation in `stockQueuedAt` order before reporting later quotations. This preserves earlier claims without creating an out-of-stock Sales Order, but every readiness call loads and walks the entire eligible branch queue; the new 30-second/focus polling multiplies that cost.

Quotation Manager gates conversion from server readiness and passes fresh detail-modal results into conversion, with backend reservation retaining authority if stock changes. The list refreshes on an interval, focus, visibility, filter changes, and actions without request sequencing, so an older response can replace newer results and temporarily leave stock actions at stale readiness.

The prior-pass Sales Executive authorization gap remains outside the quotation allocator: Sales Order list/detail reads are actor-scoped, while stats and all mutation lookups remain branch-scoped. The removed Sales Order arrival fields, routes, GRN trigger, service methods, tabs, and controls are absent from the current implementation.

<details><summary>Details</summary>

## Duplicate lines can consume the wrong exact bucket

**Confirmed.** `services/quotationStockService.js:22-33` prefers a sufficient candidate and then sorts sufficient buckets by descending available quantity. For duplicate product lines requesting 6 and 10 against exact buckets containing 6 and 10, the 6-unit line consumes the 10-unit bucket first; the 10-unit line then receives 6 and readiness becomes partial, even though assigning each line to the same-sized bucket satisfies both. Direct execution of `calculateQuotationReadiness` reproduced `available 6/6` followed by `partial 6/10` and a four-unit shortfall.

This blocks both the frontend button and `POST /quotations/:id/convert`, so the atomic reservation path never gets a chance to accept the feasible order. Allocate constrained/larger lines first or use best-fit among sufficient candidates, and add duplicate-line permutations so item ordering cannot change readiness.

## FIFO recomputation is unbounded and poll-amplified

**Likely.** `getQuotationReadinessMap` at `services/quotationStockService.js:141-173` loads every non-expired approved or accepted quotation in the branch, collects every product across that queue, loads matching Stock rows, and walks the full queue. List pagination does not bound this work because the global queue is recomputed before enriching the requested page; detail reads and `check-stock` repeat the same scan.

`QuotationManager.jsx:138-140` adds a 30-second interval plus focus and visibility refreshes, so every open client repeatedly triggers the branch-wide computation. Queue size and user count determine whether this becomes a release blocker, but the query path has no bound or materialized allocation. Add representative-volume measurement and either cache/materialize queue allocations with invalidation on Stock/quotation changes or provide an incremental query strategy before relying on polling.

## Automatic readiness refresh can settle on an older response

**Likely.** `QuotationManager.jsx:116-128` writes every completed request into the same quotation and pagination state, while the newly added timer, focus listener, visibility listener, filter changes, conversion refreshes, and initial load can overlap. There is no request generation check or abort signal. A request issued for an old search/page/readiness can therefore finish after a newer request and replace it, leaving a ready quotation disabled or an unavailable quotation enabled until another refresh; backend conversion still fails closed on the latter.

Sequence or cancel list requests and only apply the latest response for the current query.

## Sales Executive Sales Order authorization remains asymmetric

**Confirmed.** `routes/salesOrderRoutes.js:141-146` and `:324-330` scope list and detail reads to orders assigned to or created by the Sales Executive. `GET /stats` at `:198-216` remains branch-wide, and edit, cancellation request, status change, and delete use branch-only lookups at `:351`, `:441`, `:491`, and `:543`. A scoped user can receive counts for hidden orders and mutate a hidden order when its ID is known.

Apply one shared actor-aware Sales Order predicate to stats and every mutation, composed with existing branch authorization. This is an unaddressed concern from the previous pass rather than a new readiness-service defect.

## Regression coverage does not exercise the lifecycle

**Confirmed.** No repository test files cover quotation readiness, FIFO ordering, conversion reservation, approval release, or the Quotation Manager state transitions, and the backend package has no `test` script. Add service tests for partial/all/mixed/zero, competing approved/accepted quotations, exact-bucket constraints, and duplicate-line permutations; add transaction-level tests for conversion rollback/races and draft approval rejection; add UI tests for GRN-driven refresh and stale-response suppression.

</details>
