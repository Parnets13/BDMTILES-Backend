# Live FIFO quotation readiness across backend, web, and mobile

This change makes quotation readiness a live FIFO contract shared by allocation and conversion. Immutable line UOM snapshots align entered quantities with base inventory, quotation APIs and stats expose current readiness/validity/conversion state, and web/mobile views refresh nonterminal records without overlapping requests. The migration is dry-run by default and limits execute mode to evidence-backed metadata defaults. Watch for: no requirement-level blocker remains; ambiguous legacy records intentionally remain audit-only.

**Verdict**: APPROVED

## High-level view

Queue participation and conversion share one eligibility decision. Approved and accepted quotations require a valid queue timestamp and satisfied pricing approval, approved-origin sent records preserve FIFO position, and all other lifecycle or invalid-snapshot records remain physical-only.

Readiness allocates immutable quotation demand against inventory base quantities, then reports entered-unit results. Discrete quantities are floored without tolerance, configured precision is enforced before persistence, and conversion reuses the stored UOM factor and selected bucket.

Quotation endpoints, stats, and both clients consume the same live envelope. Polling settles before rescheduling and is guarded by visibility/focus, generation, and in-flight state; historical stock remains separate from live readiness.

## One eligibility contract gates FIFO and conversion

`quotationStockEligibility` drives both the shared FIFO pool and conversion gate, exposing `queueMode` and `eligibilityReason`. Ineligible legacy approvals can inspect physical stock but cannot reduce the pool seen by eligible records. Approval establishes the server-owned queue timestamp; draft-to-sent records receive none, and later acceptance joins them at the current queue tail.

## Immutable UOM snapshots keep readiness and reservation aligned

Create/edit persists entered/base units, conversion factor, version, precision, fraction policy, and canonical quantities before historical capture. Live and migration validation reject incomplete, inconsistent, over-precision, or disallowed fractional snapshots, while conversion copies the stored factor instead of resolving mutable product configuration.

Both previous blockers are resolved. A nonfractional factor-10 Box with only `9.999` Pieces now allocates zero via strict `Math.floor(maximumEnteredQty)`. A precision-2 quantity of `1.234` is rejected before persistence and is invalid in live and migration validation.

## Live lifecycle responses and stats stay consistent

List/detail/create/edit/status/validity/conversion/reversal use the shared DTO where practical. Stock-check keeps readiness at the top level while adding lifecycle, validity, conversion, quotation, and nested readiness envelopes. The quotation router applies `Cache-Control: no-store`, validates quotation/conversion IDs, and returns current readiness on stock conflicts.

Stats build one readiness map for the branch set, then aggregate live available, partial, out-of-stock, fully-converted, queued/physical-only, and none/partial/full conversion counts.

## Client refresh and conflict recovery

The web list refreshes quotations and stats together every 30 seconds after the prior request settles. Open detail polls full authoritative data for every nonterminal status, including draft, pending, and sent; its UI shows checked time, queue mode, per-line allocation/shortfall, distinct partial conversion, and historical stock only in the collapsed “At quotation creation” section with capture provenance.

Mobile always refetches detail on mount and subsequent focus, polling only while focused and foregrounded. It shows the same overall/line readiness and conversion distinctions. Both clients refetch after conversion conflicts; mobile preserves intent-scoped idempotency and order navigation.

## Validation and dry-run evidence

Backend syntax checks passed for `quotationStockService.js`, `quotationRoutes.js`, `migrateQuotationReadiness.js`, and `validateQuotationReadinessScenarios.js`; direct readiness-service and quotation-router imports also passed. `npm run validate:quotation-readiness` passed lifecycle, physical-only/queued, approval mismatch, partial conversion, historical-vs-live stock, factor-10, `9.999`-Piece discrete, and precision-policy scenarios.

`npm run migrate:quotation-readiness` inspected 11 quotations in `dry-run` mode with zero writes or index changes. It reported one invalid product reference, 13 missing UOM snapshots, 13 missing warehouse constraints, three malformed legacy approval-field sets, six ambiguous snapshot-provenance records, and two ambiguous conversion lineages. It planned four safe `snapshotCaptured` defaults; every applied-update counter remained zero.

Web `npm run build`, mobile `npm run lint`, and backend/web `git diff main --check` passed; Vite emitted only its large-chunk advisory. No migration execute command ran, no dependencies/tests were added, and the review modified no source files.
