## Scheduler startup now shares the database cleanup boundary

`start()` connects MongoDB before constructing the expiry scheduler because scheduled work depends on the database. The asynchronous bootstrap catch now always awaits `mongoose.disconnect()` before setting `process.exitCode`, including the invalid-schedule path where no scheduler handle or HTTP listener was created. This preserves the intended post-connect startup ordering without allowing a failed bootstrap to stay alive on an open Mongoose connection.

## Lease fencing and shutdown drain remain coordinated

The scheduler retains its active run promise, checks confirmed lease ownership and a local lease deadline between expiry candidates, and makes `stop()` await that promise. `server.js` awaits scheduler stop before closing the listener and disconnecting Mongoose, so graceful termination cannot remove the database underneath an active expiry batch.
