# Durable maker-checker stock adjustments and physical audits

This change replaces direct stock adjustment and audit posting with durable, branch-scoped documents that freeze submission state, route decisions through ApprovalRequest, and append deterministic StockMovement records only after independent approval. It adds canonical vectors, snapshot and journal-tail checks, exact inverse reversals, compatibility adapters, and new React workflow screens. The transaction-backed posting is a strong foundation, but permission and audit lifecycle gaps can over-authorize users or leave documents unable to complete. **Watch for:** **confirmed** compound-action privilege escalation on both compatibility endpoints; **confirmed** submitted audits that cannot be recounted after an approval conflict; **confirmed** stale-count submission after a failed frontend save; **likely** compatibility audits stranded by the create/submit transaction gap; **confirmed** stale audit totals, dropped conflict details, incomplete menu access, incorrect initial alternate-UOM previews, and omitted durable records in Stock Detail.

**Verdict**: NEEDS_CHANGES

## High-level view

The domain service now owns submission snapshots, ApprovalRequest synchronization, approval posting, and reversal. Canonical vectors exclude manual reserved/transit/short changes, while deterministic document/version/line keys make transaction retries safe.

**confirmed:** compatibility endpoints perform multiple workflow actions after authorizing any one listed permission. The audit adapter also accepts the legacy `stock.adjustment` alias, expanding an adjustment-only compatibility grant into audit creation, counting, and submission.

**confirmed:** approval-time audit conflicts persist `recountRequired` while leaving the audit submitted and its ApprovalRequest pending, but only draft audits can save counts. **confirmed:** the UI compounds this by continuing submission when its count-save request fails, which can freeze previously saved rather than currently edited counts.

**likely:** compatibility audit creation and submission can be separated by an intervening stock movement; replaying the idempotency key returns the same stale draft and cannot recover. **confirmed:** compatibility-supplied counts also bypass header aggregate recomputation, so submitted totals and classifications disagree.

**confirmed:** structured recount details are lost in the API client, menu leaves hide the workflows from submit/check/reverse-only users, initial alternate-UOM variance previews can disagree with the server, and Stock Detail does not render the durable adjustment/audit records returned by its backend.

<summary>Details</summary>

## Compatibility endpoints collapse maker, counter, and submitter authorization

**confirmed:** `POST /purchase/stock/adjust` authorizes any of `stock.adjustment.create`, `stock.adjustment.submit`, or `stock.adjustment` and then always creates and submits (`routes/purchaseRoutes.js:630`). A create-only caller can submit and a submit-only caller can create, unlike the dedicated routes.

**confirmed:** `POST /purchase/audit/submit` authorizes any of create, count, submit, or the legacy adjustment alias before performing all three audit actions (`routes/purchaseRoutes.js:801`). Require every capability represented by the compound action, or a narrow compatibility capability, and remove `stock.adjustment` from audit authorization.

## Approval conflicts leave physical audits impossible to recount

**confirmed:** approval persists `recountRequired` and returns 409 (`services/stockWorkflowService.js:482-508`) while the audit remains `submitted` and ApprovalRequest remains `pending`. Count saving accepts only `{ status: 'draft' }` (`stockWorkflowService.js:406-409`), and the UI also exposes counting only for drafts. Reopen the audit through an explicit domain transition that synchronizes or retires the pending approval, captures the recount without silently rebasing, and freezes a refreshed request on resubmission.

## Save-and-submit can freeze old counts after a failed save

**confirmed:** `saveCounts` catches API errors and resolves (`src/pages/inventory/PhysicalAudit.jsx:79-88`), then `submit` calls `submitPhysicalAudit` regardless (`PhysicalAudit.jsx:91-93`). If current edits fail to persist while older counts exist, those older values can be submitted. Rethrow or return a checked result and stop submission unless the exact current payload was accepted.

## Compatibility audit replay cannot recover from the create/submit gap

**likely:** `createSubmittedLegacyAudit` commits creation before invoking submit without a shared session (`services/stockWorkflowService.js:594-600`). A movement in that gap makes submission persist recount flags and fail; same-key retries find the same draft and retry against its unchanged baseline. Make creation, supplied-count application, and submission one transaction, or define a resumable recount operation instead of presenting the POST as self-contained.

## Compatibility counts leave audit header totals stale

**confirmed:** creation applies payload counts and saves (`services/stockWorkflowService.js:399-401`), while `matchedCount`, `shortCount`, `excessCount`, `totalVariance`, and `totalValueImpact` are recomputed only by the separate save-count path (`stockWorkflowService.js:412-417`). Compatibility audits therefore carry classified lines with zero header totals, affecting the compatibility response, lists, and stats. Centralize aggregate recomputation after every count mutation and before submission.

## Recount details disappear at the frontend boundary

**confirmed:** workflow routes return `details.recountLineIds`, and `PhysicalAudit` reads `error.details` (`src/pages/inventory/PhysicalAudit.jsx:95-98`), but the Axios interceptor copies only status, code, and message (`src/config/api.js:95-98`). Generic approval errors also serialize only the message. Preserve structured details in both paths so the fail-closed response identifies affected lines.

## Alternate-UOM preview disagrees with the first server calculation

**confirmed:** new audit lines start with conversion factor one even when entered and base units differ, and the frontend preview multiplies by that value (`src/pages/inventory/PhysicalAudit.jsx:120-123`). The server resolves the real conversion only on save, so a box-to-piece count can change variance and classification after saving. Snapshot the selected count-UOM conversion when building the sheet or return enough frozen conversion data to reproduce the server vector.

## Menu leaves hide non-creator workflow roles

**confirmed:** App routing accepts every adjustment/audit capability, but menu leaves require only `stock.adjustment.create` and `stock.audit.create` (`src/config/menuConfig.js:356,363`). Submitters, counters, approvers, reversers, and legacy adjustment users can open routes directly but cannot navigate to them. Use permission arrays aligned with the route guards.

## Stock Detail omits the durable records it fetches

**confirmed:** the endpoint returns exact-bucket `recentStockAdjustments` and `recentPhysicalAudits` (`routes/stockRoutes.js:166-167`), but the Related records view renders neither (`src/pages/inventory/StockDetailDrawer.jsx:335-345`). Add workflow cards that consume `lines` and expose document number/status, operation or count, posting version, and movement/reversal IDs.
