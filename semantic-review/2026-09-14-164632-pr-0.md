# FIFO partial quotation conversion into reserved Sales Orders

The change lets approved or accepted quotations convert either all remaining quantity or only the quantity currently allocated by FIFO, while retaining unconverted demand for later child Sales Orders. A conversion ledger, per-line converted quantities, optimistic versioning, exact stock allocation, and web/mobile controls carry that lifecycle. Exact reservation and quotation advancement occur in one MongoDB transaction, and no out-of-stock Sales Order path remains. **Watch for:** **confirmed** rejected or cancelled child orders release stock but permanently consume quotation demand; **confirmed** legacy zero UOM defaults are rejected during conversion; **confirmed** web/mobile retries generate new idempotency keys; **confirmed** migration can hide over-converted partial history; **confirmed** mobile replaces enriched quotation state with an unenriched response.

**Verdict**: NEEDS_CHANGES

## High-level view

FIFO readiness now uses each line’s remaining quantity and prefers constrained/larger lines plus best-fit exact buckets. The previous duplicate-line 6/10 case against 6/10 stock resolves fully, and conversion reuses the chosen warehouse, shade, and batch for exact-key reservation.

Full conversion requires every remaining line to be allocated. Available conversion includes fully available lines and, after explicit confirmation, allocated partial-line quantities; charges are proportional and the final child receives the monetary remainder. The transaction creates and reserves the child, advances `convertedQuantity` under `conversionVersion`, records lineage, and posts accounting only for confirmed children.

Approval rejection and cancellation return inventory but leave converted quantities, conversion state, legacy links, and charge allocations unchanged. Released demand therefore cannot be converted again.

Legacy quotation lines can carry zero `pieces` and `sqft` defaults. Child construction removes the subdocument id but forwards those zeros, defeating the pricing normalizer’s legacy-field exception.

The server has same-key replay protection, and concurrent different-key conversions are serialized by stock writes plus `conversionVersion`. Both clients create the key inside each service invocation, so retrying after an unknown network outcome becomes a new operation.

Migration backfills lineage before replacing the one-order-per-quotation index. Its preflight validates quantity equality only for records already marked `converted`; partial records can go negative and are then clamped, concealing inconsistent history.

Web reloads enriched records after conversion. Mobile writes the route’s unenriched quotation into its detail cache, removing readiness and populated child-order/history data until a later refetch.

The endpoint retains quotation and Sales Order permissions plus branch/actor-scoped lookups. No new authorization or client-controlled stock-trust gap was found in the active partial-conversion hunks.

## Released child orders leave quotation demand permanently consumed

**Confirmed.** Conversion increments each source line’s `convertedQuantity`, marks the quotation partial/full, appends the child id, and writes `QuotationConversion` at `routes/quotationRoutes.js:832-874`. Credit rejection releases only the reservation at `routes/approvalRoutes.js:410-412`. Manual cancellation does the same at `routes/salesOrderRoutes.js:503-517`, as does approved cancellation at `routes/approvalRoutes.js:316-347`; none updates the source quotation or conversion ledger.

A fully converted quotation whose only draft child is rejected remains `status=converted` and cannot be retried. A partial quotation permanently excludes the rejected/cancelled quantity from FIFO, while charge allocation at `routes/quotationRoutes.js:736-755` continues counting that child.

Add an `active`/`voided` conversion-entry lifecycle. In the rejection/cancellation transaction, lock the quotation by `conversionVersion`, void the entry, decrement its line quantities, recalculate state/status, clear `fullyConvertedAt` when reopening, and sum charges from active entries only. Preserve `convertedToSO`/`convertedAt` as historical first-conversion fields, not remaining-demand authority.

## Legacy zero UOM defaults make old quotations unconvertible

**Confirmed.** Child construction removes `_id` and always emits scaled `pieces` and `sqft`, including zero, at `routes/quotationRoutes.js:718-725`. The compatibility rule treats zero display UOMs as omitted only while input retains `_id` (`services/orderPricingService.js:20-22`); without it, zeros are supplied and fail positive-quantity validation at `services/orderPricingService.js:51-58`.

Build child UOMs from canonical box quantity and omit non-positive legacy `pieces`/`sqft`, or normalize before stripping `_id`. Add a fixture with `quantity>0`, `boxes=0`, `pieces=0`, and `sqft=0` for both conversion modes.

## Client-generated keys do not survive an ambiguous retry

**Confirmed.** The backend fingerprints `mode` and `includePartialLines` (`routes/quotationRoutes.js:579-635`), enforces unique lineage (`models/QuotationConversion.js:33-40`), and advances the quotation optimistically (`routes/quotationRoutes.js:827-860`). Web generates a default key whenever conversion is invoked (`BDMTILES-Fronted/src/services/salesService.js:89-93`); mobile generates one inside every call (`BDMTILES-SalesApp/src/features/sales/salesDocumentService.js:37-42`).

If the server commits but the response times out, pressing Convert again can consume the next remaining quantity under a new key. Generate the key when UI intent is created, retain it with the exact payload through transport retries and uncertain failures, and rotate only after definitive success or a deliberate new intent.

## Migration can clamp inconsistent partial history after a non-atomic preflight

**Confirmed.** Preflight subtracts mapped quantities at `scripts/migrateQuotationConversions.js:35-54`, but checks remainders only inside `if (quotation.status === 'converted')` at lines 56-65. Backfill caps `convertedQuantity` with `Math.min` at line 136. A partial record with five units remaining and a linked child for ten passes preflight and is recorded as exactly full, hiding five excess units.

Sales Order, conversion-ledger, and quotation writes are independent at lines 98-154; only afterward does the script drop the old unique index and create replacements at lines 157-176. A mid-run failure leaves partial backfill state.

Reject negative remainder for every quotation and validate before subtraction. Make backfill resumable with per-record verification, then create/verify ledger indexes, reconcile all records, and drop the legacy unique index only after a final no-drift check. Do not clamp financial lineage.

## Mobile loses readiness and child-order presentation after conversion

**Confirmed.** Detail reads add live readiness and history (`routes/quotationRoutes.js:343-360`), while conversion returns the unenriched transaction document (`routes/quotationRoutes.js:592-601,904`). Mobile replaces detail cache with it at `BDMTILES-SalesApp/src/features/sales/QuotationDetailScreen.jsx:40-45`, then derives controls and children from `stockReadiness` and populated `convertedSalesOrders` at lines 89-93 and 220-261.

After partial conversion, the screen falls into the no-stock note and child ids lack order number/status until refetch. Invalidate/refetch detail on success, or return the same enriched projection from conversion.

## Partial-conversion regression coverage is absent

**Confirmed.** No matching automated tests cover quotation conversion in the reviewed trees. Backend syntax checks, a direct FIFO allocator smoke test, the frontend production build, and scoped SalesApp ESLint passed.

**Not tested:** same/different-key transaction races; rejection/cancellation reopening; legacy zero-UOM conversion; charges across several children; migration interruption/rerun and index cutover; or web/mobile retry and cache transitions. Add allocator/UOM service tests, transaction tests against a replica set, migration fixtures, and client state tests.
