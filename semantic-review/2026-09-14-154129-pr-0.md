# Selective removal of Sales Order stock-arrival handling

The working tree removes the rejected out-of-stock Sales Order lifecycle from the seven reviewed files while preserving reservation, release, fulfilment, quotation, square-foot, status/cancellation, dashboard layout, dealer-request, and Sales Executive scoping changes. Sales Orders no longer carry arrival fields, react to GRN posting, expose arrival endpoints, or render arrival controls. Two remnants prevent the cleanup from being complete: the quotation conversion client still accepts the former options body, and Sales Executive ownership scope still stops at list/detail reads. **Watch for:** **confirmed** `convertQuotation` still exposes the OOS-era request-body hook; **confirmed** Sales Executives can still obtain branch-wide stats and mutate Sales Orders excluded from their scoped reads.

**Verdict**: NEEDS_CHANGES

## High-level view

The rejected Sales Order stock-arrival topology is otherwise absent. The model and inventory utility contain only normal reservation/release/fulfilment state, GRN approval only posts accepted inventory and PO quantities, Sales Order routes have no arrival queries or actions, and the dashboard/view expose no arrival status or controls.

Quotation-required creation and live quotation stock checks remain available; square-foot metadata and detail presentation, status/cancellation and fulfilment actions, the dashboard redesign, and dealer-request client APIs also remain.

**Confirmed:** quotation conversion still takes and transmits an arbitrary options object introduced for the rejected `allowOutOfStock` flow. Removing that body parameter is required to eliminate the final client API remnant without removing `checkQuotationStock`.

**Confirmed:** the new Sales Executive predicate is applied to list and detail reads only. Stats, edit, cancellation request, status change, and deletion continue to authorize by branch, so scoped users see inconsistent counts and can act on orders hidden from their list if they know an ID.

## OOS-era conversion payload remains exposed

**Confirmed.** `src/services/salesService.js:89` changed `convertQuotation` from an ID-only call to `convertQuotation(id, options = {})` and sends that object as the conversion request body. The prior pass identified this extension as the client hook used by `allowOutOfStock`; leaving it in place means not every rejected Sales Order OOS surface has been removed. Restore the ID-only conversion call while retaining `checkQuotationStock` at line 90 and the surrounding quotation APIs.

## Sales Executive ownership scope does not cover stats or actions

**Confirmed.** `routes/salesOrderRoutes.js:144-146` and `:326-330` restrict Sales Executive list/detail reads to orders assigned to or created by the actor. `GET /stats` still uses only `{ branch: req.branchId }` at `:200`, while update, cancellation request, status transition, and delete lookups remain branch-only at `:357`, `:441`, `:491`, and `:542` respectively. This produces dashboard counts for inaccessible orders and leaves a horizontal-authorization gap on mutating endpoints.

Use one shared actor-aware Sales Order scope for list, detail, stats, edit, cancellation, status, and deletion. Compose it with the existing branch authorization and retained assignment/creator predicate.
