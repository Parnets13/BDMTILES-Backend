# Durable maker-checker stock workflows with atomic compatibility paths

This follow-up verifies the Stock Adjustment and Physical Audit workflows after the nine first-pass findings were addressed. Compatibility creation/submission is now transactional and capability-complete, while recount explicitly cancels stale approval state before resubmission. Aggregate recomputation, conflict detail propagation, base-UOM sheets, menu access, generic approval dispatch, and Stock Detail lineage are present. **Watch for:** **confirmed** malformed cycle/spot scope IDs silently widening to the whole warehouse; **confirmed** audit count and submit permissions not functioning as independent capabilities; **confirmed** adjustment “Save & submit” retries creating duplicate drafts after creation succeeds.

**Verdict**: NEEDS_CHANGES

## High-level view

Canonical vectors, frozen snapshots, journal-tail checks, ApprovalRequest synchronization, transactional posting, and exact inverse reversal now share one domain service. The nine previously reported issues are resolved in the current diff.

**confirmed:** cycle-count and spot-check filters discard invalid stock/product IDs. If no valid ID survives, the service builds a whole-warehouse sheet rather than rejecting the requested scope.

**confirmed:** count saving and submission are restricted to `createdBy` despite separate audit capabilities, and the frontend implements every submit as a count-save followed by submit. Delegated counters cannot count another maker’s sheet, while submit-only actors cannot reach the submit endpoint.

**confirmed:** adjustment “Save & submit” does not retain a successfully created draft when submission fails. The modal remains in create mode, so retrying creates another draft.

## Cycle and spot scope filters fail open on malformed identifiers

**confirmed:** `auditScopeFilter` removes values that fail `mongoose.isValidObjectId`, then adds an `_id` or product constraint only when at least one value survives (`services/stockWorkflowService.js:312-317`). A spot check with `stockIds: ['bad-id']` therefore becomes `{ branch, warehouse }` and includes every bucket. Reject malformed IDs and require a supported filter for non-full scopes so the persisted scope and hash cannot represent a silently broadened request.

## Audit capability split is blocked by maker-only service rules and save-before-submit UI

**confirmed:** the count route requires `stock.audit.count`, but `savePhysicalAuditCounts` rejects actors other than `createdBy`; `submitPhysicalStockAudit` applies the same maker-only restriction (`services/stockWorkflowService.js:416-419, 459-463`). The dedicated count permission cannot delegate counting, and submit permission is usable only by the creator.

**confirmed:** the page shows Submit based on `stock.audit.submit`, but `submit()` first calls `saveCounts()` (`src/pages/inventory/PhysicalAudit.jsx:92-96, 145-146, 180`). Because that request requires `stock.audit.count`, a submit-capable actor without count permission receives a 403 before the authorized submit request. Allow counters and submitters to perform their respective transitions, and save during submission only when the actor can count and has changed the count revision.

## Adjustment create success is lost when immediate submission fails

**confirmed:** `save(true)` creates and then submits without retaining the returned draft before the second request (`src/pages/inventory/StockAdjustmentPage.jsx:115-124`). If creation commits and submission fails or its response is lost, retrying while `mode === 'create'` creates a second draft. Store the created document and switch to edit/resume mode before submission.
