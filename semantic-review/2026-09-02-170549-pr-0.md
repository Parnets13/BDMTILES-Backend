# Quotation product browser with branch inventory and customer pricing

The redesign replaces type-ahead selection with a 50-item, filterable browser that combines branch-wide stock with customer-context pricing, then feeds selected products into the existing authoritative preview/create flow. The new endpoint cannot return a non-empty product page because its product projection is incompatible with the pricing resolver; that projection also omits the tier and minimum-rate inputs needed for correct displayed prices. **Watch for: Critical — confirmed at `routes/quotationRoutes.js:230-251`: active products are rejected as inactive, and a status-only fix would make displayed rates fall back to MRP.**

**Verdict**: NEEDS_CHANGES

## High-level view

The browser asks the existing resolver to price each product for the selected dealer, dealer type, or walk-in scope and aggregates stock across the authenticated branch. Projected products omit fields the resolver requires, so the integration fails before results reach the UI and would still misprice products after a partial fix.

## Incomplete product projection prevents browsing and loses authoritative rates

**Critical — confirmed.** `routes/quotationRoutes.js:230-251` passes each projected product directly to `resolvePricing`. `services/pricingResolver.js:111-114` treats an object with `_id` as already loaded and requires `status === 'active'`; because line 231 omits `status`, the resolver rejects the first product and aborts the entire page. A direct smoke check with the route's projected shape returned `422 Product P1 is not active.`

A status-only fix would leave incorrect pricing. `services/pricingResolver.js:28-46` selects from `dealerRate`, `wholesaleRate`, `retailRate`, `distributorRate`, `builderRate`, and `projectRate`, then reads `minimumSellingRate`, but line 231 selects none of them. Browser cards would fall back to `mrp` and report a zero minimum while labeling the result authoritative. Include `status`, every resolver tier field, and `minimumSellingRate` in the projection, or pass IDs so the resolver loads complete products.

</details>
