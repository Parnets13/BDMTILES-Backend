# Integrated stock lifecycle, journal, and quotation readiness

This change replaces direct stock mutations with an append-only, base-UOM journal and extends it through reservations, picking, transfers, dispatch, returns, durable adjustments, audits, alerts, and quotation conversion. The backend generally uses transactions and deterministic movement keys, while web and mobile consume richer readiness and reconciliation contracts. Release is blocked by lifecycle work that is not scheduled, incomplete maker-checker and lineage consumption, and clients that reinterpret base quantities as boxes. **Watch for:** **confirmed** expired reservations require a privileged manual call; **confirmed** return and audit workflows permit lineage or actors to be reused; **confirmed** web/mobile quantity labels disagree with the backend UOM contract.

**Verdict**: NEEDS_CHANGES

## High-level view

`StockMovement` introduces signed vectors, immutable UOM snapshots, intent hashes, operation keys, and transaction-scoped guards. Durable adjustment/audit creation does not expose the service's idempotency support, and audit approval excludes creators and submitters but not counters.

Fulfillment now reserves base units, posts sorting discrepancies, consumes stock at dispatch, and records item-level delivery/recovery lineage. Transfer receipt can close omitted lines as shortages, while Sales Return caps only the invoice line rather than the selected delivery item or discrepancy.

Partial closure releases reservation, credits the confirmation receivable, and constrains the final invoice to net dispatch. Remaining-cancellation approvals are absent from the generic approval registry, and reservation expiry has no automatic execution path.

Quotation readiness is FIFO-aware, branch-scoped, no-store, and transactionally rechecked. Quotation detail polling is present, but operational stock views and the mobile quotation list remain manual-refresh surfaces; the mobile list also ignores derived expiration status.

Most migrations default to dry-run and preserve ambiguous records. Quotation conversion migration defaults to execution, while UOM migration can miss incomplete lines in mixed embedded arrays.

<summary>Details</summary>

## Reservation expiry has no automatic execution path

**Confirmed, P0:** `services/reservationExpiryService.js` contains the transactional release, but `routes/systemRoutes.js` exposes it only as a `system.management` endpoint. `server.js` registers no timer and `package.json` has no worker command, so elapsed `reservationExpiresAt` values can leave `reservedQty` unavailable indefinitely. Add a single-owner scheduled worker or deployable worker command with locking and observable retries.

## Durable stock drafts lose retry identity

**Confirmed, P1:** `services/stockWorkflowService.js` supports `sourceKey` fingerprints for adjustments and audits, but `routes/stockAdjustmentRoutes.js` and `routes/physicalStockAuditRoutes.js` pass neither an `Idempotency-Key` nor a source key. A response-loss retry can create two drafts that are later posted independently. Require branch-scoped idempotency on creation and replay the fingerprint-checked document.

## Physical counters can approve their own counts

**Confirmed, P1:** `services/stockWorkflowService.js` records `countedBy`, while `ensureChecker` checks only `createdBy` and `submittedBy`. A counter can approve the same variance when another user submits it. Exclude every material `lines.countedBy` actor or enforce an equivalent independent-count policy.

## Delivery-specific Sales Return allowances are reusable

**Confirmed, P1:** `services/salesReturnLineageService.js` compares a customer return with the selected item's full `acceptedQuantity` without subtracting earlier returns; discrepancy lineage is not capped by `discrepancy.boxes`. `services/salesReturnService.js` and `routes/salesReturnRoutes.js` aggregate prior usage only by invoice item, so the same delivery item or discrepancy can be reused until the invoice cap is reached. Consume active quantity by `deliveryItem` and `discrepancy` inside approval.

## Omitted transfer receipt lines become permanent shortages

**Confirmed, P1:** when `routes/stockTransferRoutes.js` receives an `items` array, it first sets every line to fully short, applies supplied rows, and completes the transfer without requiring every line ID. A truncated payload removes source total stock, records omitted quantities as short, and prevents later receipt. Require each dispatched line exactly once or add a non-terminal partial-receipt state.

## Stock balances use the wrong display UOM

**Confirmed, P1:** `services/stockMovementService.js` returns Stock buckets in `Stock.baseUnit`, but `BDMTILES-Fronted/src/pages/inventory/StockPage.jsx` labels them with `product.unit`. A Box-sold/Piece-stored product displays 100 pieces as 100 boxes and multiplies by `piecesPerBox` again. Render base buckets in `row.baseUnit`; use explicit server conversions for commercial and coverage views.

## Quotation entry says boxes while the API interprets product UOM

**Confirmed, P1:** `BDMTILES-Fronted/src/pages/sales/AuthoritativeQuotationModal.jsx` and `BDMTILES-SalesApp/src/features/sales/CreateQuotationScreen.jsx` label quantity as Boxes but omit `unit` from payloads. `services/quotationStockService.js` interprets the number as the product's commercial UOM, so non-Box products reserve and invoice a different quantity than the operator entered. Send and display the selected authoritative UOM.

## Remaining-cancellation approvals are absent from the approval inbox

**Confirmed, P1:** `models/ApprovalRequest.js` allows `sales_order_remaining_cancellation` and `routes/salesOrderRoutes.js` creates it, but `APPROVAL_TYPE_PERMISSIONS` and `APPROVAL_REFERENCE_TYPES` in `routes/approvalRoutes.js` omit it. Generic approval listing and action cannot surface the stock/finance closure. Register and domain-route the type, or provide an intentional dedicated queue.

## Migration safety is inconsistent

**Confirmed, P1:** `scripts/migrateQuotationConversions.js` is dry-run only when `--dry-run` is supplied, and `package.json` invokes it without a flag. The nominal command immediately rewrites lineage, creates indexes, and can drop the legacy unique index. Require explicit `--execute` and reject unknown or contradictory flags.

**Confirmed, P1:** `scripts/migrateUomLineage.js` selects documents using only `items.0.baseUnit` and `items.0.uomVersion`. A mixed array with a migrated first line and incomplete later line is skipped, leaving later stock calculations on defaults. Match any incomplete line, report residuals, and use compare-and-set updates.

## Live operational stock views do not poll

**Likely, P1:** `BDMTILES-Fronted/src/pages/inventory/StockPage.jsx`, `StockAlerts.jsx`, and `StockDetailDrawer.jsx` have only mount/filter/manual refresh. `BDMTILES-SalesApp/src/features/sales/QuotationsScreen.jsx` also has pull-to-refresh only and renders persisted `status`, unlike the polling/effective-status behavior in web `QuotationManager.jsx` and mobile `QuotationDetailScreen.jsx`. Add single-flight foreground polling or mutation-driven invalidation and render derived lifecycle fields.
