## Invalid expiry schedules leave startup connected but non-serving

**Confirmed:** `server.js` connects MongoDB before calling `startReservationExpiryScheduler()`, and the scheduler validates `RESERVATION_EXPIRY_SCHEDULE` before returning its stop handle. If validation throws, `start().catch(...)` logs the failure and assigns `process.exitCode = 1`, but it neither calls `shutdown()` nor disconnects Mongoose. The live MongoDB connection can keep the process running even though `app.listen()` was never reached, leaving an unhealthy instance that does not exit for its supervisor to restart. Disconnect Mongoose in the failed-start path, or validate scheduler configuration before opening the database connection.
