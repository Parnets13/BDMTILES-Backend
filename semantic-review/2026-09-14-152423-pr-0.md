# Out-of-stock quotations without out-of-stock Sales Orders

The change lets unavailable products enter quotations, records a stock snapshot, adds live stock checks, and expands quantity handling to boxes and square feet. It also mixes in dealer-request linking, Sales Executive scoping, a Purchase Requisition product browser, product-size automation, and an alternate path that creates draft out-of-stock Sales Orders and promotes them after GRN posting. That alternate Sales Order path is rejected by the intended design and unsafe: it can strand orders, double-reserve inventory, and confirm orders without normal accounting side effects. **Watch for:** **confirmed** live stock never unlocks conversion through the current handler; **confirmed** stock evidence is client-supplied and absent from request-prefilled quotations; **confirmed** edits erase stock metadata; **confirmed** OOS Sales Order refresh is non-atomic and fail-open; **confirmed** quantity/square-foot edits show stale totals or send rejected payloads; **confirmed** PR search can display an older query; **confirmed** unrelated product-size and modal changes must not be blanket-reverted.

**Verdict**: NEEDS_CHANGES

## High-level view

Unavailable products can now be quoted and checked again before the existing transactional conversion/reservation path creates a Sales Order. **Confirmed:** the frontend rechecks the immutable creation snapshot after the live check succeeds, so an OOS quotation cannot be converted from either the table or detail modal.

The backend retains a second path enabled by `allowOutOfStock`, which creates an unreserved draft Sales Order and asks GRN posting to promote it later. **Confirmed:** it clears OOS tracking before reservation succeeds, omits ledger posting on late confirmation, and has no concurrency guard.

Availability has no single authoritative contract. **Confirmed:** ordinary quotations trust browser-supplied flags, dealer-request prefills omit them, and the live check aggregates branch stock while reservation requires an exact warehouse/shade/batch allocation.

The square-foot UI conflicts with backend normalization. **Confirmed:** quantity changes skip preview even though totals depend on quantity, and square-foot entry rounds boxes up while sending the original square feet alongside them.

The Purchase Requisition search and product-size work are independent improvements, not rollback collateral. **Confirmed:** PR search drops a newer query while an older request is in flight, and clearing size or pieces-per-box retains the previous computed square-foot value.

1. **Rejected OOS Sales Order path — confirmed** — Draft OOS Sales Orders, GRN promotion, arrival endpoints, fields, and UI remain wired in. Remove those selective hunks and keep quotation-level stock checks plus normal conversion/reservation.
2. **Fail-open late confirmation — confirmed** — Arrival refresh clears OOS tracking before reservation and suppresses reservation failure; successful promotion also omits receivable posting. Remove the alternate promotion path rather than maintaining a second confirmation transaction.
3. **Duplicate reservation race — confirmed** — Concurrent manual/GRN refreshes can reserve the same order twice from stale order documents. Removing the OOS Sales Order refresh path eliminates this race.
4. **Live-stock conversion deadlock — confirmed** — The detail modal unlocks from live stock, then `handleConvert` rejects from the old creation snapshot; the list never live-checks. Gate on live results and let normal atomic reservation make the final decision.
5. **Unauthoritative/incomplete stock evidence — confirmed** — Creation trusts client flags, while dealer-request prefills always submit unmarked stock state. Derive and persist quotation availability on the server for every creation path.
6. **Branch-total/allocation mismatch — confirmed** — The stock endpoint promises readiness from branch totals that may not satisfy one warehouse/shade/batch reservation. Return allocation-capable readiness using the same rule as conversion.
7. **Edit-time stock metadata loss — confirmed** — Repricing rebuilds items without `outOfStock` or `stockAtQuotation`. Preserve or recompute server-managed stock metadata on update.
8. **Stale quantity pricing — confirmed** — Quantity/square-foot changes do not refresh line totals, tax, summary, or approval exposure. Reprice every quantity-affecting edit.
9. **Square-foot payload mismatch — confirmed** — `ceil` produces boxes inconsistent with the simultaneously submitted square feet, and detail APIs omit `sqftPerBox`. Choose one canonical UOM contract and include the display field in API projections.
10. **Stale PR product results — confirmed** — A newer debounced query is discarded while an older request is loading, whose response is then displayed. Supersede/sequence requests and clear pending debounce on unmount.

## Rejected draft-OOS Sales Orders remain wired through conversion and GRN

**Confirmed.** `routes/quotationRoutes.js:558-702` accepts `allowOutOfStock`, relaxes warehouse validation, creates an unreserved draft Sales Order, and persists arrival state. `routes/purchaseRoutes.js:12,515-524` invokes `triggerStockArrivalForGRNProducts` after GRN commit; `routes/salesOrderRoutes.js:558-640`, `models/SalesOrder.js:60-67,145-187`, and `utils/salesOrderInventory.js:138-276` implement the corresponding lifecycle. The frontend remnants are in `SalesOrderDashboard.jsx`, `SalesOrderView.jsx`, and `salesService.js`.

Keep the quotation stock snapshot and `GET /quotations/:id/check-stock`, then use normal conversion once stock is live-ready. Remove `allowOutOfStock`, Sales Order arrival fields/endpoints/UI, and the GRN trigger. `GET /sales-orders/oos-pending` is also shadowed by the earlier `GET /:id`, while the “Stock Arrived” tab requests `isOutOfStock=true` even though successful refresh sets it false.

## Arrival refresh can lose inventory and accounting state

**Confirmed.** `refreshSalesOrderStockArrival` sets `stockArrivalConfirmed=true` and `isOutOfStock=false` before reservation (`utils/salesOrderInventory.js:218-239`). Missing warehouse or a lost stock race is suppressed, and the draft is saved outside future OOS queries/buttons. The endpoint still returns `ready=true` and says the order is confirmed/reserved (`routes/salesOrderRoutes.js:574-576`).

**Confirmed.** Late promotion sets `status='confirmed'` without the receivable posting performed by normal conversion (`routes/quotationRoutes.js:711-721`). Concurrent manual/GRN refreshes can load the same unreserved order, each decrement stock, and race full-document saves; atomic stock decrements prevent negative stock but not duplicate reservation for one order.

## Live quotation readiness never reaches conversion

**Confirmed.** The detail modal shows Convert when `stockCheck.allStockAvailable` becomes true (`QuotationManager.jsx:895-987`), but passes the unchanged quotation to `handleConvert`. That handler recomputes from persisted creation flags and rejects every formerly unavailable quotation (`QuotationManager.jsx:128-142`). The list action is permanently disabled by the same snapshot and performs no live check.

Use the live result as the UI gate and call the normal conversion endpoint; backend reservation remains the race-safe authority. Both automatic and manual check failures are swallowed, so surface the failure and preserve retry.

## Quotation stock state is client-controlled and allocation-blind

**Confirmed.** `AuthoritativeQuotationModal.jsx:174-188` computes flags from browser state, and `routes/quotationRoutes.js:379-411` copies those request fields back after pricing. The server does not snapshot Stock, so stale clients or direct callers can persist arbitrary availability.

**Confirmed.** Dealer-request prefill returns quantities without stock (`routes/dealerOrderRequestRoutes.js:343-351`); the modal creates those rows with `stockAvailable:0` but no stock snapshot/flag (`AuthoritativeQuotationModal.jsx:105-126`). It therefore submits `stockAtQuotation:null` and `outOfStock:false` regardless of availability.

**Confirmed.** `GET /quotations/:id/check-stock` sums branch lots by product (`routes/quotationRoutes.js:766-786`), while reservation requires exact warehouse, shade, and batch. Fragmented stock or a missing warehouse can produce “All stock arrived” followed by conversion failure. Derive creation and live readiness server-side under the same allocation rule.

## Repricing an edit erases the quotation stock snapshot

**Confirmed.** Creation restores stock fields because `deriveOrderPricing` rebuilds items without them (`routes/quotationRoutes.js:379-411`; `services/orderPricingService.js:225-265`). Update calls the same pricing function and assigns `fields.items` without restoration (`routes/quotationRoutes.js:470-516`), resetting an OOS draft/pending quotation to default false/null. Preserve by product identity or recompute transactionally.

## Box and square-foot editing conflicts with pricing

**Confirmed.** `AuthoritativeQuotationModal.jsx:320-328` skips preview for quantity/square-foot changes, although pricing multiplies rate, discount, tax, and approval exposure by quantity. Submit recalculates, but the visible total can differ from the saved total.

**Confirmed.** Square-foot entry stores `quantity=ceil(sqft/sqftPerBox)` while retaining and sending the original sqft (`AuthoritativeQuotationModal.jsx:445-456,174-188`). Backend normalization requires both values to represent the same box count (`services/orderPricingService.js:45-72`), so 10 sqft at 6 sqft/box becomes 2 boxes plus 10 sqft and returns 422. Reprice quantity edits and either convert sqft to full boxes or submit only one canonical UOM.

**Confirmed.** Quotation/Sales Order detail renders `item.product?.sqftPerBox`, but `routes/quotationRoutes.js:326` and `routes/salesOrderRoutes.js:338` omit it from population. Retain the display changes and add the projection.

## Purchase Requisition search can settle on an older query

**Confirmed.** `ProductSearchCell.doSearch` refuses a request while `loadingRef` is true (`PurchaseRequisition.jsx:53-74`). A second debounced query exits and is never retried; the first response then appears under the newer input. Retain the portal dropdown/expanded modal, but sequence or abort requests and clean up the debounce.

## Sales Executive scope stops at read endpoints

**Confirmed.** New list/detail predicates restrict Sales Executives to assigned/created orders (`routes/salesOrderRoutes.js:144-146,327-334`), but stats, update, status, delete, and check-stock remain branch-scoped. Counts do not match rows, and an ID known through another response can mutate an unreadable order. Retain actor scoping and `salesExecutive` attribution for the separate mobile work, then apply one predicate consistently.

## Product-size automation can retain stale conversion data

**Confirmed.** `ProductMaster.jsx:253-265` only writes `sqftPerBox` when calculation succeeds. Clearing size/pieces or setting pieces to zero leaves the old read-only value. Keep expanded sizes, calculation/display, and `StockPage.jsx` modal widths; clear or explicitly preserve/re-enable manual sqft when inputs are incomplete.
